# 金融垂类资源治理

## 目标

将用户 GitHub starred 项目、组织 Fork、官方披露和市场数据源整合为一个可审计的
金融垂类资源池，服务于独立的股票/ETF/财报/公告/宏观信息收集，不把金融数据混入节能
或 AI 行业监测仓库。

## 资源分层

| 层 | 内容 | 进入生产的条件 |
| --- | --- | --- |
| 官方事实源 | 交易所、监管机构、上市公司 IR、SEC 和官方宏观统计 | 记录来源、发布时间、原始链接和抓取状态 |
| 数据适配器 | AKShare、Baostock、yfinance 等 | 字段契约、点时校验、失败降级和许可证审查 |
| 研究组件 | 方向、筛选、回测、组合和风险项目 | 独立测试、样本外验证、不能直接产生投资结论 |
| 研究型 AI | TradingAgents、FinGPT 等 | 只解释已验证事实，不生成未经证据支持的评分或建议 |
| 资源索引 | awesome-quant 等目录 | 只用于发现候选项目，不是生产依赖 |

## 准入规则

1. 业务相关性优先于 star 数量和项目知名度。
2. 以 2026-10-06 为快照日，最近 183 天没有有效提交的项目标记为过时，只保留为研究参考。
3. 活跃项目也必须经过许可证、来源稳定性、数据再分发、点时一致性和本仓库数据契约检查。
4. 任何第三方叙述、AI 输出或技术指标都不能替代交易所、监管机构、上市公司和基金文件等原始证据。
5. 行情、财报、公告、宏观数据和行业信息使用各自的日期与频率，不能用旧值伪装成当日数据。
6. 金融简报只描述已验证事实、数据日期、来源和不确定性，不提供买卖建议或实盘承诺。

## 当前资源判断

详细资源清单见 [`config/finance-resources.json`](../config/finance-resources.json)，信息源登记见
[`config/finance-information-sources.json`](../config/finance-information-sources.json)。当前 26 个直接金融
资源和 1 个相邻 AI 基础设施资源中，AKShare 是生产数据适配的首要候选；TradingView API 仍需
授权和稳定性审查。
其余项目按行情监控、研究分析、风险监控、回测、金融 AI 和知识参考分别管理。

组织 Fork 仍是固定版本、上游同步和审计边界，不代表已经把上游完整代码合并进
`stock-research`。生产 Workflow 只调用经过本仓库标准化和质量检查的输出。

## 后续工作

- 建立官方披露、公司公告和宏观统计的来源清单及日期证据字段。
- 将行情、ETF 和财报快照统一写入可追溯的原始与标准化产物。
- 为每个数据源记录源版本、请求参数、抓取时间、数据日期、行数、错误和降级路径。
- 通过独立的金融日报输出市场事实；行业 BU 只消费经过确认的关联摘要。
